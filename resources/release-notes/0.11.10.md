## Features

- **Jump straight to any settings page from the keyboard.** Four new shortcuts open the section you want without walking the settings tree: `⌘⌥S` (Application settings), `⌘⌥A` (AI & Models), `⌘⌥T` (Appearance), and `⌘⌥B` toggles the built-in browser. They use `⌘⌥` rather than `⌘⇧` because the mnemonic letters in that family were already taken, and they deliberately avoid the native menu and DevTools bindings.
- **The browser info capsule now tells you where browser tools will actually go.** A read-only indicator sits at the right end of the capsule: a globe when the built-in browser is on (tools stay in-app), a Chrome mark when it is off (tools drive your real Chrome through WebBridge), and a warning state when WebBridge can't be reached — click it to open the Chrome Web Store page for the extension you need to install. When the state genuinely can't be determined, it stays quiet rather than claiming something is missing.
- **File preview remembers where you were reading.** Each open tab keeps its own scroll position, so switching between files — or having a file re-read from disk after an external edit — no longer snaps you back to line one. The position follows the preview through inline, split, and maximized layouts; closing a tab forgets its position.
- **A "new session" button appears in the session list when the sidebar is hidden.** Hiding the sidebar used to take the New Session button with it, leaving only the keyboard shortcut and the app menu. The button now moves to the left of the session list header — same icon, same behaviour (click to create, `⌘`/`Ctrl`-click to open in a new pane, right-click to open in a new window), and it lands at roughly the same screen position as the sidebar button, so toggling the sidebar barely moves it.
- **Documentation search now works in Peng Agents Backend sessions too.** The docs tools were previously available only in Claude sessions. They now reach every session through the shared MCP pool, including the very first moments of a brand-new workspace where you have no sources configured yet — which is exactly when setup guidance is most useful.
- **Knowledge history distillation can go full-screen.** A toggle in the dialog's top-right expands it to nearly the whole window and back; it resets when the dialog closes.

## Improvements

- **Smart Snapshot is now on by default**, correcting the "off by default" note in 0.11.9. Any existing configuration is treated as enabled unless you explicitly turned it off. On macOS, leaving it on is safe even without Accessibility permission — the hotkey simply never fires rather than prompting.
- **The Smart Snapshot shutter sound now plays reliably on both platforms.** It previously rode the system alert channel — macOS routed it through the alert volume (silent if you keep alerts at zero, even with normal output volume) and Windows played the sound scheme's default beep (silent under the "No Sounds" scheme). Both platforms now play the sound themselves through the regular output mixer with three levels of fallback, so the effect toggle is the only thing that decides whether you hear it. It fires just before the capture, which doubles as immediate feedback that the key chord was recognised.
- **Automatic retries during provider congestion went from 3 to 10.** The 45-second silence watchdog now widens itself to match the retry backoff, so a long, legitimate wait is no longer mistaken for a hang.
- **Image generation is preferred over drawing images with code.** The model is now told to reach for the image generation tool first, inspect the result for text and number rendering, and fall back only if the result doesn't hold up — with a short explanation of why.
- **The app no longer sends anything to the upstream documentation team.** The docs MCP server exposes a `submit_feedback` write tool, and the upstream server actively instructs models to call it; it would have sent model-written prose — potentially quoting you — with no confirmation in any permission mode. It is now blocked at four independent layers. Read-only documentation *search* is unaffected: it sends a query string, is triggered by your own intent, and appears as a visible tool call.
- **Smaller install.** A 630 KB prebuilt bridge binary that was packaged on every build but never started, plus an entire unused server package and a dead HTTP pool-server path, have been removed.
- **@-mention gained Tab completion.** `Tab` completes the current path — a directory gains a trailing `/` and keeps the menu open so you can descend further, a file completes to its full path — while `Enter` still selects and inserts the chip.

## Bug Fixes

- **All saved logins could disappear at once.** Three faults compounded: the credential store was written directly over the live file (so a process killed mid-write left a truncated file), anything that failed to decrypt — including that truncated file — was deleted outright with no backup or warning, and a failure to read the machine identifier silently fell back to a different key, making an intact store look unreadable and get deleted. Writes are now atomic, an unreadable file is renamed aside rather than deleted, and a transient failure to derive the key aborts the read instead of re-keying. The store also honours `CRAFT_CONFIG_DIR`, so development and tests stop touching your real credentials.
- **Signing back in didn't take effect until you started a new session.** The running agent was only rebuilt when the connection, provider or auth type changed — not when credentials appeared or disappeared — so a session that started without credentials stayed broken forever. Credential presence is now part of the restart signature; token refreshes don't trigger a needless rebuild.
- **Errors named a provider you never chose.** Signed in with a ChatGPT Plus subscription, a failure could report "No API key found for azure-openai-responses". When credentials couldn't be read, the compatibility check treated *any* provider as compatible, silently fell back to the SDK default model, and surfaced that model's missing-key error. The connection's intended provider is now carried independently of whether its credentials were readable, mismatches fail fast, and the message names the real provider ("Not signed in to …", or "belongs to provider X but authenticated with Y"). Switching models or connections mid-session goes through the same check, and a session is no longer stuck behind a stale resolution error after you switch to a working model.
- **macOS sessions could spin forever with no error.** After a failed attempt the engine reported that it would retry, which held the error back — but the retry itself hung in an untimed network call (SSE headers defaulted to five minutes; OAuth token refresh had no limit at all). Four fixes: OAuth token endpoints get a 30-second timeout, the retry hold releases the moment the run settles or 45 seconds of total silence pass, queued messages survive a terminal error so follow-up runs aren't dropped into a closed stream, and the provider transport timeout defaults to 120 seconds.
- **Windows sessions froze with every tool pinned and no output.** The JSONL bridge to the engine subprocess could die in one direction only — the subprocess could still receive, but nothing came back — and the pre-tool-use handshake had no timeout, so every tool waited forever and each retry pinned another one. The handshake is now acknowledged immediately and gives up after 45 seconds with an actionable error; a 10-second heartbeat detects a dead bridge, aborts cleanly, and respawns the subprocess with the conversation intact on the next turn.
- **Long-running Bash commands were killed by that same watchdog.** The 30–40 second stall threshold was shorter than the 120-second window Bash is legitimately allowed, so anything slow in between was aborted. The subprocess now emits its own heartbeat independent of the ping path, Bash calls carry a bounded lease that suppresses the kill until their real timeout, and one final probe runs before termination so a late reply cancels it.
- **Approving a Bash command on Windows could freeze the session in a loop.** Where the bridge genuinely died during approval, each round froze for 130–143 seconds and the model then retried the same command, freezing again. An unapproved lease is now capped at 45 seconds (bringing the worst case to about 60), and after three stalls in ten minutes the message stops suggesting a resend and describes the environment-level problem instead. Both sides of the bridge now write diagnostics to `<session>/logs/`, so a failure can be attributed to the side that actually died.
- **PowerShell commands were always rejected in safe mode on Windows** with "validator root not set" — the validator script's location was registered through an API this build never called. The script path now falls back to the module's own directory, is copied into packaged resources (with a build-time check so it can't go missing again), is registered at startup, and is warmed asynchronously on Windows so the first tool call doesn't absorb the startup cost.
- **File preview didn't notice edits made outside the app.** Content was read once and never re-read, because opening the same path again reused the existing tab. The preview now watches the file's directory and re-reads on change, keeping the old content visible until the new read lands. Watchers are reference-counted between the file tree and the preview, so collapsing the tree no longer cancels the preview's updates.
- **Sub-directories never loaded in @-mention.** A stale 50-entry cache keyed on the first character swallowed every later query, so descending into a folder returned nothing. The cache is now invalidated per directory prefix, a query containing `/` switches to directory-navigation semantics, and the backend search starts its walk from the real directory instead of fuzzy-matching the whole tree.
- **The browser status bar became unreadable under custom skins.** Its background tracked a variable that the panel-opacity slider drives toward transparent, letting page text show through and overlap the labels. It now uses the shared opaque popover base, with the toolbar row behind it blurred, and the activity indicator's glow is tinted by the site's own theme colour (and disabled under reduced-motion).
- **Deleting a knowledge source left its scheduled ingestion behind.** Removing a source now clears the matching schedule and its bookkeeping. The scheduling dialog and the automations page also show which library a schedule targets, orphaned entries are badged, and an orphaned schedule warns once instead of on every run.
- **The Themes help link opened a 404.** The link behind the help button in Settings → Appearance pointed at a documentation path that upstream had moved. Several documentation tool names that upstream renamed were also stale in six places, including prompts that were teaching the model to call a tool that no longer exists.
- **A third-party MCP tool named `submit_feedback` could be blocked outright.** The outbound block matched the bare tool name after stripping any MCP prefix, so an unrelated source with a tool by that common name was globally refused with an error pointing at the docs server. It is now scoped to the documentation server we mount ourselves.
- **Starting a session could hang when the documentation endpoint was unreachable.** The connection was awaited with no timeout on the session's tool-registration path. It now gives up after 4 seconds and continues in the background; that session simply has no documentation tools, and the next registration round picks them up.

## Breaking Changes

- None. All changes are backward-compatible.
